## Reflexão
O Qodana detetou o método com quatro parâmetros (`Method with too many parameters`) e o gate falhou; ao reduzir para três parâmetros passou. Em `main` a análise completa encontrou 3 problemas (2 métodos e 1 construtor), pelo que o limiar de 3 é sensível: baixá-lo para 2 aumentaria muito os problemas e subi-lo para 4 eliminaria quase todos. O limiar é absoluto e não há uma estratégia no livro para este cheiro, por isso o valor 3 é uma escolha convencional e pode haver falsos positivos (por exemplo construtores de objetos de valor) ou falsos negativos (parâmetros agrupáveis num objeto mas abaixo do limite). Tal como nos outros gates, um PR sem código novo falha com `Nothing to analyse`.
